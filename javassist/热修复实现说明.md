# 美团式热修复：怎么实现、为什么这么实现

对照课程 `ManiuJavaSsit`（Javassist + Transform），在本工程用 **AGP 9 能用的方式** 做了同一件事：编译期改 class，运行时按 bool 判断走补丁或原代码。

---

## 1. 要解决什么

美团 Robust 的核心不是替换整个 dex，而是：

1. **编译期**给每个方法开头插一段判断
2. **运行时**如果该类挂了补丁对象，就反射调补丁；否则继续执行原方法体

插完之后的方法形态如下（逻辑等价）：

```java
public String getMessage() {
    ChangeQuickRedirect redirect = changeQuickRedirect;
    if (redirect != null && PatchProxy.isSupport($args, this, redirect, false, "methodId")) {
        return (String) PatchProxy.accessDispatch($args, this, redirect, false, "methodId");
    }
    // 原始编译代码
    return "原始编译代码";
}
```

`changeQuickRedirect` 是编译期插进每个类的静态字段。没加载补丁时它是 `null`，判断为 false，走原代码，性能开销主要是一次空指针判断。

## 2. 整体结构

```
编译期（javassist Gradle 插件，不进 APK）
  HotfixPlugin          挂到 Android 编译流水线
  HotfixTransformTask   拿到本 module 的 class 目录 / jar
  HotfixWeaver          Javassist 改字节码

运行时（app 源码，打进 APK）
  ChangeQuickRedirect   补丁接口（isSupport / accessDispatch）
  PatchProxy            插桩代码调用的桥
  HotfixManager         反射设置 changeQuickRedirect
  HotfixTarget          被修复的演示类
  HotfixTargetPatch     模拟“临时加载”的补丁
```

插件是 **编译期工具**，必须用 `plugins { alias(libs.plugins.hotfix) }` 引入，不要写成 `implementation`。写成依赖会把 Gradle API、Groovy、Javassist 打进 APK。

---

## 3. 为什么不照抄课程的 Transform

课程代码（2021，AGP 3.x）：

```groovy
project.android.registerTransform(new ModifyTransform(project))
```

`Transform` 流程是：遍历 `directoryInputs` → Javassist 改 `.class` → `FileUtils.copyDirectory` 交给下一环。

AGP 8 起 **Transform API 已删除**，本工程是 AGP 9.1.1，再 `registerTransform` 编不过。官方替代是：

```groovy
variant.artifacts
    .forScope(ScopedArtifacts.Scope.PROJECT)   // 只改本 module，不改依赖
    .use(taskProvider)
    .toTransform(ScopedArtifact.CLASSES, 输入jar, 输入目录, 输出jar)
```

对应关系：

| 课程 | 本工程 | 原因 |
|---|---|---|
| `ModifyPlugin.registerTransform` | `HotfixPlugin` + `ScopedArtifacts` | Transform 已删除 |
| `ModifyTransform` 读 directory/jar | `HotfixTransformTask` | 同一件事：拿输入、改、交给下一环 |
| `addCode` 里 `System.out.println($1)` | `HotfixWeaver` 插入 `PatchProxy` | 课程是演示 Javassist API；目标是热修复 |
| 改完 `copyDirectory` | 输出一个 class jar | AGP 9 的 CLASSES transform 出口是文件 |
| 手写 `META-INF/gradle-plugins/*.properties` | `gradlePlugin { }` | 新 plugins DSL 还需要 Maven 插件标记 POM |
| 旧 `uploadArchives` + `maven` 插件 | `maven-publish` 上的同名任务 | Gradle 7 删除了旧 maven 插件 |

`Scope.PROJECT` 只处理 app 自己的 class。课程用了 `SCOPE_FULL_PROJECT`，但 jar 是原样 copy、并不改依赖，效果接近；PROJECT 更干净。

## 4. 插件入口怎么声明

`javassist/build.gradle`：

```groovy
plugins {
    id 'java-gradle-plugin'   // 编译期生成 properties + 插件标记 POM
}
gradlePlugin {
    plugins {
        hotfix {
            id = 'com.stone.hotfix'
            implementationClass = 'com.stone.interview.javassist.HotfixPlugin'
        }
    }
}
```

- `id`：APP 里写的插件名
- `implementationClass`：`Plugin<Project>` 实现

不要手写 `src/main/resources/META-INF/gradle-plugins/xxx.properties`。`java-gradle-plugin` 会在 `pluginDescriptors` 任务里生成同一份文件，并额外发布：

`com.stone.hotfix:com.stone.hotfix.gradle.plugin:版本`

`plugins { id("com.stone.hotfix") version "1.0.3" }` 先解析这个标记 POM，再找到真正的 `javassist-hotfix` jar。课程那种只放 properties 的方式，只适配旧的 `apply plugin:` + `buildscript.classpath`。

发布到本地 Maven：

```bat
.\gradlew.bat uploadArchives
```

产物在 `javassist/repo`。根工程没有 javassist 子模块（它是独立插件工程），所以根目录的 `uploadArchives` 只是转去执行 `javassist` 自己的发布任务。

APP 引入（`settings.gradle.kts` 的 `pluginManagement` 里把本地仓库放最前）：

```kotlin
maven { url = uri(rootDir.resolve("javassist/repo")) }
```

```kotlin
alias(libs.plugins.hotfix)  // com.stone.hotfix:1.0.3
```

改完插件必须先 `uploadArchives` 再编 APP，否则还在用旧版本。版本号没涨时，Gradle 可能缓存旧 jar，需要升版本或 `--refresh-dependencies`。

## 5. withPlugin 是什么意思

```groovy
project.pluginManager.withPlugin("com.android.application", hook)
```

意思是：**等 `com.android.application` 这个插件已经 apply 之后，再执行 hook**。

- 如果 APP 的 `plugins {}` 里 android 已经写在 hotfix 前面，hook **马上**跑。
- 如果有人把 hotfix 写在 android 前面，此时还没有 `androidComponents` 扩展，直接 `getByType` 会崩；`withPlugin` 会等到 android apply 完再跑。
- 所以不依赖 plugins 块的书写顺序。课程能直接 `project.android.registerTransform`，是因为他们 `apply plugin: 'com.android.application'` 写在 `com.javassist` 前面，且用的是旧 API。

library 模块同样挂一份，纯 `java-library` 没有 Android CLASSES 产物，不挂。

## 6. 编译产物放在哪里

分三层，不要混：

**1. kotlinc / javac 的原始 class（还没插桩）**

```
app/build/intermediates/built_in_kotlinc/debug/compileDebugKotlin/classes
app/build/intermediates/javac/debug/compileDebugJavaWithJavac/classes
```

**2. 本插件的输出（插桩后的 class jar，AGP 指定，dex 读这个）**

```
app/build/intermediates/classes/debug/PROJECT/insertHotfixDebug/classes.jar
```

`toTransform` 把任务接到 `ScopedArtifact.CLASSES` 上，AGP 自动生成这个路径。必须写入 `output` 指向的这个 jar，后面的 `transform*Asm`、`dexBuilder` 才用得到插桩结果。

**3. 给人看的清单（不是给打包用的）**

```
app/build/hotfix/insertHotfixDebug.txt
```

流水线：

```
compileKotlin / compileJava
        ↓  原始 class 目录
insertHotfixDebug          → intermediates/classes/.../insertHotfixDebug/classes.jar
        ↓
transform*ClassesWithAsm
        ↓
dexBuilder / package       → APK
```

`toTransform` 会让 dex 自动依赖插桩任务，不必再手写 `compile.finalizedBy`、`dex.dependsOn`（那种容易和 `packageDebugResources` 循环依赖）。

## 7. Javassist 具体改了什么

对每个可改的类：

1. 增加字段  
   `public static volatile ChangeQuickRedirect changeQuickRedirect;`
2. 每个方法开头插入 bool 判断（见第 1 节）
3. 构造方法用 `insertBeforeBody`，保证插在 `super()` **之后**。插在 `super()` 之前会 VerifyError。
4. 跳过：接口/枚举、R/BR/BuildConfig、Hilt/Dagger 生成类、`PatchProxy` 自身（否则递归）、abstract/native/synthetic/`<clinit>`

`insertBefore` 里的 `$args`、`$0`、`$r` 是 Javassist 特殊变量：参数数组、this、返回类型转换。

课程 `addCode` 是按参数个数 `System.out.println($1)`，用来证明“能改方法”。这里换成 Robust 判断，才是热修复。

## 8. 运行时怎么走到补丁

1. `HotfixManager.loadAndApply(HotfixTarget.class, patchClassName, classLoader)`
2. 反射 `Class.forName` 加载补丁类（演示用同一 ClassLoader；正式环境换成 `DexClassLoader` 加载下发的 dex）
3. 反射写入 `HotfixTarget.changeQuickRedirect = ReflectRedirect`
4. 下次调用 `getMessage()`：字段非空 → `isSupport` 为 true → `accessDispatch` 再反射 `HotfixTargetPatch.invoke`
5. `clear()` 把字段置回 null，恢复原代码

补丁 `isSupport` 只认 `getMessage` / `add`，避免构造方法也被拦。

首页 **热修复**：

- 调用原方法 → `原始编译代码`，`1+2=3`
- 加载热修复 → `热修复后的代码`，`1+2=103`
- 卸载 → 回到原始结果

Logcat 过滤 `Hotfix`。

## 10. 关键文件

| 文件 | 作用 |
|---|---|
| `javassist/build.gradle` | 插件 id、发布本地 Maven |
| `javassist/.../HotfixPlugin.groovy` | 挂 ScopedArtifacts |
| `javassist/.../HotfixTransformTask.groovy` | 编译期任务入口 |
| `javassist/.../HotfixWeaver.groovy` | Javassist 改字节码 |
| `app/.../hotfix/PatchProxy.java` | 运行时桥 |
| `app/.../hotfix/HotfixManager.java` | 反射挂补丁 |
| `app/.../hotfix/HotfixTarget.kt` | 被修复类 |
| `app/.../hotfix/patch/HotfixTargetPatch.java` | 补丁实现 |
